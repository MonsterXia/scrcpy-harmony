# Scrcpy Harmony 1.0.5 全量 UI 重构设计

日期：2026-11-03（Asia/Shanghai）

状态：**用户于 2026-11-03 确认此版方向与设计并授权分阶段实施；UI-1～6 已实现；最终交付与未验收矩阵以[连续实施记录](../../maintenance/v1.0.5-ui-completion.md)为准。**
源码核对基线：`895fd10`，设计时 `package.json` 版本为 `1.0.4`；后续本地候选使用 `1.0.5-dev.0`，不改变公开发行状态。

## 1. 版本目标与已确认方向

用户要求 1.0.5 对 UI 全量重构，认为刚改过的投屏、升级界面相对满意。用户已选择“轻量桌面工作台：清爽、统一，兼顾日常使用和调试”，并要求先看主窗口和应用管理的浏览器草图。

目标：让连接设备、投屏、安装应用等高频任务一眼可见，让日志、终端、布局检查仍有足够工作空间；所有页面、弹窗、反馈、菜单和窗口形成同一套视觉与交互规则。

全量指所有现有用户界面都纳入覆盖与验收，不等于全部重写实现。投屏和更新严格保留现有设计、布局、交互与状态机，仅做回归检查；不迁移其 token 或样式。

### 方向比较

| 方向 | 收益 | 代价 | 结论 |
| --- | --- | --- | --- |
| 轻量桌面工作台 | 日常入口清晰，工具分组稳定，兼容高密度工作区 | 需要处理侧栏与最小窗口空间分配 | **用户已选择** |
| 专业调试控制台 | 多面板与快捷操作优先 | 初次使用复杂，日常投屏入口不够突出 | 不采用为全局风格；保留调试页的密度 |
| 设备卡片中心 | 设备与常用动作直观 | 开发工具层级更深，多设备能力容易扩大范围 | 不采用；设备概览吸收其清晰呈现方式 |

### 本版边界

- 保留 Electron + React + TypeScript、MobX/observer、SCSS Modules、本地 Luna 与 xterm 的技术基础。
- 不借 UI 重构增加文件管理、录屏、无线配对、多设备并行投屏、手机到电脑剪贴板等功能。
- 不变更 HDC、捕获、升级版本选择与安装机制。确有 UI 状态表达缺口时，先检查既有 IPC；新接口单独设计，禁止仅为展示编造数据。
- 设置、列表、导航的旧偏好应继续读取；语言切换仍由用户重启生效，不自动打断会话。
- 本文的颜色、尺寸、分期与组件划分为设计建议，除上述整体方向外不视为用户已批准的细节。

## 3. 信息架构与主窗口

建议结构：平台标题栏 → 左侧导航与设备入口 → 右侧页面标题、操作区和内容区。避免在底部再常驻一整条重复设备状态栏。

- 侧栏顶部：产品标识、设备选择器（名称、连接状态、可辨识标识），刷新放在选择弹层内；无设备时入口仍可用。
- “设备”分组：设备概览、应用管理、截图。
- “调试”分组：终端、日志、进程、布局检查、WebView。
- 侧栏底部：设置、关于。现有原生菜单的检查更新、Beta Update、帮助、退出保留并与设置共用真实状态。
- 页面标题区：标题、简短说明/数量；右侧最多一个强调主操作，其余采用次按钮或更多菜单。
- “开始投屏”固定在内容区顶部公共设备操作位置；无设备禁用并给出原因，不只留下一个无说明图标。
- 非当前页面保持既有会话策略。设置和关于属于应用级内容，无设备也可访问。

### 空间与适配

- 标准布局建议侧栏 200px，页面内边距 24px；紧凑时为 16px。保持 960×640 可操作，不以增大最小窗口规避设计问题。
- 宽度不足 1100px 时默认折叠为约 64px 图标栏，提供 tooltip、可访问名称及显式展开入口；展开作为覆盖层，不挤压工作区。实际阈值在原型和 Electron 验证后定稿。
- 布局检查在紧凑宽度将属性栏切为可展开面板/抽屉，截图与树保留；宽窗口恢复三栏。验证已保存的 split weights，不能把旧比例直接应用到不适配布局。
- 不依赖 hover 暴露唯一操作；常用操作支持键盘。主要按钮、表格和日志不得被标题栏拖拽区域吞掉点击。
- 默认窗口建议后续评估 1120×760，按显示器可用工作区收敛；尊重已有窗口尺寸。此项待视觉验证，不在规划阶段修改。

## 4. 视觉系统

基调：中性底色、清楚的文字层次、蓝色强调、少量圆角。浮层允许适度玻璃效果，表格、终端、日志使用实色底以保证对比度与性能。

| 项目 | 建议规则 |
| --- | --- |
| 色彩 | 浅色底 `#F5F6F8`、内容 `#FFFFFF`、主文字 `#20242B`；深色底 `#17191D`、内容 `#202329`、主文字 `#F0F2F5`；强调色以现有蓝色为基础，按对比度调整 |
| 语义色 | 成功、警告、错误、离线各有文字/图标，不仅凭颜色区分；禁用、悬停、选中、focus 独立定义 |
| 字体 | 系统无衬线；页面标题 22/28px，分组 14/20px，正文 13/20px，辅助 12/18px；终端/日志/技术值使用等宽字体 |
| 间距 | 4/8/12/16/24/32px，避免每页自由取值 |
| 控件 | 常规高度 32–36px，图标 16–18px；密集工具栏可用 28px，点击区域与间距单独保障 |
| 圆角 | 输入/按钮 8px、内容块 12px、浮层 12–16px；投屏和更新已有特殊形态保留 |
| 层级 | 主要通过底色、留白、细分割线区分；仅弹层使用明显阴影，不将所有参数都包成卡片 |
| 动效 | 普通反馈 120–180ms，参考投屏已有 160ms；尊重 reduced-motion，不给日志/列表连续更新做入场动画 |
| 可访问性 | 明确 focus-visible、原生 button/label 语义、弹窗焦点约束和关闭后恢复；正文目标对比度至少 4.5:1，功能图形/边界至少 3:1，最终实际测量 |

主窗口新增 token 集中在 `workspace/Workspace.module.scss`，仅在 workspace 根作用域生效；使用既有 store.theme 选择双主题。为严格保留投屏和升级设计，本版不以修改全局 theme.json 或生成文件来批量替换主题。后续工具窗口显式接入时再提炼可复用局部层；复杂组件通过适配层接入，避免散落的全局 `.luna-*` 覆盖。

### 一致的状态规则

每页记录：初次加载、刷新中、成功、空内容、筛选无结果、失败、设备断开、权限/能力不支持（有证据时）。

- 初次加载给结构稳定的占位；刷新保留旧数据但明确标记刷新中，跨设备立即清空旧内容。
- 空列表和请求失败必须区分；失败有重试/下一步，技术细节按需展开或复制。
- 用户点击后立即给忙碌状态并抑制重复提交。没有真实百分比时显示不定进度，安装只报告已知的逐包进度与最终结果。
- 成功轻提示，失败保留可操作信息；耗时安装进度在当前界面可追踪。本版不新增通用任务中心。
- 危险确认包含目标名称、动作后果与明确动词按钮，默认焦点落在取消；外部数据按文本渲染/转义。
- 设备切换或断连使旧请求结果失效；不擅自重放安装、删除、终端命令等写操作。

## 6. 技术分层与迁移约束

建议新增有限的共享 UI 层（具体文件名由实现者结合仓库习惯确定）：`AppShell`、`DeviceSwitcher`、`PageHeader`、`ActionBar`、`StatusBadge`、`EmptyState`、`AsyncState`、`ConfirmDialog`、`DetailDrawer`。

保留 Luna 的 DataGrid、Logcat、DomViewer、ImageViewer、SplitPane 等复杂能力，通过局部包装统一布局、密度、主题和语义；简单导航/按钮/表单可以逐步使用项目 React 组件。禁止一次性替换全部组件库或重写终端/日志引擎。

| 修改范围 | 优先入口 | 风险控制 |
| --- | --- | --- |
| 应用外壳 | `main/App.tsx`、`components/workspace/*`、`main/store/index.ts` | 持久 panel ID 保持兼容，未知 ID 回退 overview；应用级设置不因 target key 重建 |
| 页面与状态 | `main/components/*`、对应 store | 保留设备代次隔离、异步结果失效与已有事件退订 |
| 隐藏面板 | `App.tsx` 的 Panel | 隐藏区域退出 tab 顺序和辅助技术树，保留挂载；切回后恢复焦点、表格/终端尺寸 |
| 主题与组件 | 主窗口 workspace 局部样式、`share/renderer/` 的独立窗口适配 | 先做组件样板验证，再迁移页面；保持投屏/升级及共享全局主题不变 |
| 原生窗口/菜单 | `src/main/window/`、`src/share/main/` | drag/no-drag、交通灯/Windows 控件、菜单图标与状态，单列跨平台验收 |
| 国际化 | `src/common/langs/`、`src/share/common/langs/` | 中英文同步、aria/tooltip/确认框全覆盖；不翻译设备原始数据 |

切页不能统一等同于断开会话：终端保留；日志沿用暂停/恢复；WebView 隐藏停止轮询。避免主题重渲染造成重复订阅或捕获重启。组件生命周期若需调整，单独给回归证据。

全量范围包含工具菜单打开的应用自身日志终端与 Electron 进程管理器（`src/main/lib/menu.ts`、`src/share/renderer/terminal/`、`src/share/renderer/process/`）。外部系统终端和 Chromium DevTools 的内部界面不重绘，仅验收入口、宿主窗口与打开行为。

## 8. 验收门槛与证据

### 视觉与可操作性

- 8 个功能页 + 设置/关于 + 应用自身日志窗口/Electron 进程管理器 + 所有弹窗/菜单/全局状态逐项打勾；投屏和更新单独列回归记录。

### 功能与性能

- 真机主线：连接 → 概览 → 投屏；安装/覆盖/拖入 → 列表刷新；多终端切换；日志暂停/筛选/导出；截图与布局；WebView；设备断连/切换。
- 回归投屏画面/触摸/输入/全屏/置顶/自动隐藏及更新所有结果分支，不能以模拟原型通过代替。
- 同机同设备与 1.0.4 建立基线：主窗口启动、切页、应用列表首批可用时间、日志连续输出、空闲 CPU/内存。至少重复 5 次记录中位数和范围，分开冷/热状态。
- 建议性能预算：无设备的界面反馈在下一次绘制即可见；交互流畅性用时间线检查长任务。可比关键耗时/空闲资源若恶化超过 10%，先复测并解释，不能把网络/设备抖动直接归因 UI。
- 保留列表/日志已有容量与虚拟化能力，不新增周期设备采集、逐帧 React 更新或全屏大面积动态模糊。
