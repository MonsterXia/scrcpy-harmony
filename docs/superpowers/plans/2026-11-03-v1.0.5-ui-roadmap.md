## 跨阶段固定规则

1. 不增加依赖或更换组件库；复杂列表/日志/终端保留原引擎。应用协议、设备命令与捕获/升级逻辑不随 UI 搬迁。
2. 不改变现有持久 panel ID；未知值回退概览。应用级设置不随设备 key 重挂载。保留现有设备级异步代次隔离。
3. 只在主窗口命名空间使用新 token；不改全局 `theme.json`/生成文件或共享全局选择器来强行统一。独立工具窗口后续显式接入。
4. 双语文案同步；不显示不存在的电量/实时 CPU/连接方式等信息。设备类型仅在现有数据有依据时呈现。
5. 每阶段执行定向行为测试、lint/i18n 和构建；交互/异步边界补测试，纯样式以实际截图/尺寸检查验收。
6. 每阶段将源码、静态检查、模拟 UI、真实 Electron、真机、三平台证据分别记录到 RUNBOOK；历史维护欠账不会因 UI 合并而关闭。

## 交付节奏

UI-1 为第一批可审查代码；随后按 UI-2、UI-3、UI-4、UI-5、UI-6 推进。每阶段控制改动范围，完成验证再推进。后续阶段开始时将本表的接口、源码与测试列表展开成独立执行计划，避免跨多轮时根据旧源码盲写。

开发预发布建议在 UI-3、UI-5、UI-6 后分别形成候选；具体编号、创建 PR、合入与发布按后续实际状态执行，当前不改发行版本和线上 Release。
